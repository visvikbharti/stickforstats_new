- [x] **The backend's Docker HEALTHCHECK was passing vacuously — FIXED 2026-07-14.**
      Found while verifying the `06bd9a4` deploy. `HEALTHCHECK CMD curl -f http://localhost:8000/api/health/`
      — **that path does not exist (404)**. But plain HTTP is 301-redirected to HTTPS by
      `SECURE_SSL_REDIRECT` *before routing*, and **`curl -f` treats a 301 as success (exit 0)**.
      Executed on the live host:

          raw (as the healthcheck ran it)      -> http_code=301, curl -f exit=0   <- "healthy"

      with Django 500-ing on every request — Docker would never have restarted a wedged backend, and
      any orchestrator watching health was being lied to.

      route (`api/v1/urls.py:227`), which reports **database connectivity**, not just liveness.
      Verified non-vacuous in the running container: real path → **200/exit 0**, bogus path →
      **404/exit 22**. **Needs a backend image rebuild to take effect.**

## The rule that has to survive this list

**Mutation-check every regression test you write.** Put the bug back; if the test still passes, it
tests nothing. Seven of the eight adversarial rounds in the power arc were needed because a green
test was mistaken for a working one. And verify the mutation *actually applied* — a substitution that
silently fails to match gives you a green run and a lie.
