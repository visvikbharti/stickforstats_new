## The one thing worth reading

Six sessions of defects turned out to be **one defect wearing six faces**:

> **The report is assembled from the specification, not from the execution.**

`assumptions_checked` was the *requirements list* — what a test NEEDS — published as though it
were a statement about what we DID. Same shape in every prior instance: `similar_shapes`
(declared in a table, no validator), the `ASSUMPTION_UNREPORTED` verdict (in the enum, the DB,
the migration, the API docstring and the React component; emitted by nothing), `p_match`,
`assumptions_reported_in_text`, `group_sizes`, `rows_sequential`. In each case the declaration
is load-bearing for the OUTPUT but not for the EXECUTION, so the two drift — and when they
drift the output wins, because the output is what gets rendered.

Measured extent before the fix: **22 of 25 test types** listed `independence` as checked while
the audit trail recorded `not_applicable`. Eight examined **nothing at all** and still returned
`confidence_score: 1.0`, `can_proceed: true`, `violations: []` over the live endpoint.

### Why the existing defences did not catch it

Each has a blind spot, and they are worth knowing:

- **Construction-time invariants** (`_assert_every_requirement_is_implemented`) see *static*
  mismatches — a requirement with no validator. They cannot see a validator that **exists and
  declines**, because declining depends on the DATA.
- **"Make it unrepresentable"** works when the wrong thing is a *shape* (a `confidence` field on
  `Rule`). It does nothing when a correct-shaped value arrives from the wrong source.
- **Mutation testing inherits the blindness of the assertion.** It proves a test is not vacuous
  *relative to the property that test asserts*. If the asserted property is a label rather than a
  behaviour, it certifies a test that certifies a lie. Demonstrated:
  `test_no_test_type_produces_zero_checks_with_full_confidence` was written in the v1.2.0 audit
  **for this exact defect**, names the property correctly in its own docstring, and passed for
  eight broken test types because `len(assumptions_checked) > 0` was satisfied by the
  requirements list unconditionally.

### Two accomplices

**Defaults launder ignorance into confidence.** `field(default=None)`, `getattr(x, "f", False)`,
`dict.get(k, d)`, `passed=True`, `except Exception: pass`. Each turns "we don't know" into a
specific, usually optimistic value.

**Defence in depth hides the corpse.** Rank-test silence has 3 independent gates and
correctly-powered-paper silence has 2 — counted by RUNNING mutations, not by reading. Worse,
`rows_sequential` + `cascade_engine` are two dead gates **in series**: open the upstream one
alone and real independence violations appear and are silently swallowed.

### Five independent inventions of the same missing type

The clearest evidence the architecture is missing something the code keeps reaching for:

| | |
|---|---|
| `AssumptionReporting` | `evaluable: bool` + `reason` |
| `appropriateness` | `Silent(reason)` |
| `ConsistencyVerdict` | `checkable: bool` + `reason` |
| `TestResolution` | `ambiguous: bool` + `reason` |
| `GuardianAuditEntry` | `result ∈ {pass, violation, skipped, not_applicable, not_performed}` |

Five places arriving at *"a result that might not have been computed, plus why"*, and none of
them a shared type. `None` is overloaded to mean both "not applicable" and "never computed".

## What landed

### `92d004d` — the flagship endpoint reaches the appropriateness engine

`3efa98d`'s message ("both pipelines now read one implementation") was **false**:
`evaluate_claims` had exactly ONE caller, the legacy validator. Proven by execution first — one
manuscript, three paths: engine direct = 1 finding, legacy validator = 1 finding,
`POST /api/v1/verify/analyze/` = HTTP 200 with **no** `rule_id`, no `appropriateness` key.

Wired at `reanalysis_engine.verify_claim` — the single per-claim funnel both `verify_manuscript`
and `verify_segments` pass through. Findings are a separate channel and never move a verdict.
Also fixed: the bundle disclosure audit saw only the claim's own file (measured cost of widening:
flat ~5 ms/claim from 1 to 50 files).

### `f979b89` — two false clean bills, live in the released v1.2.0

`consistency_core.py` is byte-identical between the v1.2.0 tag and this branch, so this was the
deployed behaviour of the statcheck tier — the always-available path that runs on every paper
without data.

```
t(18) = 3.30  → the paper's own statistic implies p = .00398
  reported p = 0.0000000001  → INCONSISTENT 'major'   ✓
  reported p = 2.83e-91      → consistent   'none'    ✗   (88 orders of magnitude out)
  paper says p < .0001       → consistent   'none'    ✗   (40× overclaim)
```

The second is not e-notation-specific: `p < .001` is ubiquitous. Both are the F-06 defect the
module's own comment warns about, surviving one branch to the left — and `p_matches` had already
been fixed for the identical trap in `c8ab999` while the neighbour was left broken.

**The fix nearly shipped something worse.** Reading e-notation at true precision makes the
interval astronomically narrow, while `p_matches` compares against data re-run from DEPOSITED
tables, which are rounded. Measured over 400 correct papers, false-DISCREPANT rate by relative
floor: `0.00 → 82.5%`, `0.02 → 13.2%`, `0.05 → 0.2%`, `0.10 → 0.0%`. Floored at
`REANALYSIS_P_REL_FLOOR = 0.10` (provisional; belongs in the B1 pre-registration). The flat
`1e-12` epsilon also went — it made the comparison INERT below 1e-12, i.e. in exactly the omics
literature that motivated the fix.

### `69b4568` — tripwire for two dead gates in series (tests only)

### `f16a54a` — Guardian reports what it EXAMINED

`assumptions_checked` now derives from the audit trail; new `assumptions_not_evaluated` carries
the rest; a `none_evaluated` warning fires when NOTHING ran (cox_regression over HTTP: confidence
1.000 → 0.444). Deliberately scoped to "nothing ran", not "something was skipped" — the latter
would re-rate essentially every check the product performs.

### `0ffdb37` — small-N power finding made attributable

The document-wide `N = <int>` minimum reported a 512-participant RCT as **"N = 3"** because of an
`n = 3 technical replicates` aside — user-reachable on `POST /api/v1/manuscript/analyze/`.
Retirement was recommended by review and was the **wrong** fix: it drops a genuinely underpowered
n=4-per-arm trial to the green *"Pass — statistical quality meets reviewer expectations"* banner.
Trading a false accusation for a false reassurance is a worse trade here. Replaced with the
claim's **own degrees of freedom** (`sum(df) + 1`, a guaranteed lower bound) — the false
accusation goes, the true positive stays. Chi-square excluded: its df is `(r-1)(c-1)`.

## Proposed architecture work (not started — needs a decision)

1. **Publish coverage everywhere** (done for Guardian; not yet for the disclosure audit).
2. **One `Evaluated[T] | NotEvaluated(reason)` type**, replacing the five hand-rolled versions.
3. **The ledger is the only input to the report** — generalise `f16a54a` so reporting an
   unperformed check is not writable.
4. **Ban the forgiving read** (`getattr`/`.get` with a default) at any boundary feeding an
   assertion. Lintable.
5. **House rule: assert the trace, not the label.**

(1) and (5) are partly landed. (2) and (3) change contracts across five modules and the API
shape — they are a decision, not a refactor.
