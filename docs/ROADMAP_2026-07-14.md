# Roadmap — from 2026-07-14

## Where the project actually is

Be honest about this, because the next decision depends on it.

**The statistics engine is now genuinely good.** The screen-facing power path was cross-checked
against statsmodels across 22 designs — every t variant × every tail, unequal arms, ANOVA k=3/4/5,
both sample-size solvers, minimum detectable effect balanced and unbalanced, correlation power —
with a worst disagreement of **2.4 × 10⁻⁸**. The 50-digit engine agrees with scipy to 4.4e-16. The
exported R and Python scripts are *executed* against `pwr` and statsmodels and land on the same
numbers the screen shows. That is a real, defensible foundation, and very few tools in this space
can say it.

**The surrounding application is where the bugs now live**, and they are all one of four classes
(`DEFECTS_AND_PATTERNS_2026-07-14.md`). Today alone, outside the power module: confidence intervals
covering 94.3% instead of 95%, and every ANOVA effect size labelled "negligible".

**The guard rails are weaker than they look.** CI's eslint lints zero `.jsx` files. 21 backend tests
fail where CI cannot see them. A flaky timing test silently blocked every production image push. A
green badge has not been evidence for some time.

So the sequencing is: **ship the correct statistics, then make the guard rails real, then build.**
Building new surface on top of guard rails that do not guard is how the last eight rounds happened.

## Phase 1 — Ship and stabilise (days)

1. ~~**Deploy `main`.**~~ ✅ Done — live is `cfe14c1`.
2. **Make CI mean something.** ✅ *Mostly done:* eslint now runs with `--ext .js,.jsx,.ts,.tsx` (764
   files, was 293 with **zero** `.jsx`), `no-use-before-define` is an **error**, and lint is in
   `docker-build`'s `needs:` so it gates the image push. **Still open:** the 21 hidden backend
   failures, and `continue-on-error` on `sdk-test` + Playwright.
3. **The receipt key.** ✅ *Hardened* — and the "unsigned in production" claim that used to sit here
   was **false** (production has a stable key; see `STATUS_2026-07-14.md` §4). Signing is now
   fail-closed, ephemeral key ids are fingerprinted, and the bundle refuses to ship a public key that
   cannot verify the signature beside it.
   **Still open — the real fix: a KEYRING.** Only one key is held at a time, so `verify()` and the
   downloadable bundle can only ever speak for the *current* key. Rotating it makes every previously
   issued receipt un-exportable (an honest 409 now, rather than an artifact that reads as a forgery —
   but still a dead end). The receipt is the moat; it must survive a key rotation. Hold a set of
   known keys: **verify against any known `kid`, sign with the newest.** Store the issuing key's PEM
   (or kid → PEM) so a bundle is always self-consistent, and serve every known public key from JWKS.
4. **Close the remaining Class A / Class B instances** listed in `TODO_2026-07-14.md`. They are small,
   they are known, and they are exactly the ones that come back.

*Exit criterion:* live == `main`; a red lint or a red test cannot ship an image; no `||`/`??`/bare
`else` remains on a value that names a kind of thing; **a key rotation does not invalidate a single
issued receipt.**

## Phase 2 — Verify the rest of the app the way power was verified (weeks)

The power module got eight adversarial rounds and is now trustworthy. **No other module has had
that.** The same treatment, module by module, in descending order of what a user would act on:

1. **Confidence intervals** — just found a 94.3% "95%" interval. The rest of the module has not been
   audited. Start here: it is the module whose *entire subject* is calibration.
2. **Guardian** (assumption checking → recommendation → report). Design-aware as of `747b848`, but its
   correlation and one-sample-t fallbacks are still missing.
3. **Regression** (robust / quantile / stepwise were dead code *and* broken as recently as `17ef3f8`).
4. **Bayesian / p-curve** — PR C from the 2026-06-05 audit was never started, and that audit found 24
   bugs.

**The method is the point:** an adversarial reviewer that must **execute, not read**; mutation-check
every regression test; execute the exported artifact rather than eyeballing it. Reading found nothing
for three rounds. Running found a 34-point contradiction in the first minute.

## Phase 3 — The product thesis (months)

The strategy documents say: **the product is manuscript verification; the moat is the reproducibility
receipt.** Both are half-built, and the half that is built is not currently signed.

- **Manuscript verification engine** — 9 of 19 TODO items open (`MANUSCRIPT_MODULE_TODO_2026-06-24.md`):
  PDF provenance mapping, discipline profiles, A5 detection. The 10,103-paper census established that
  **3.5% of papers have a checkable statistic** — know that number before promising coverage.
- **Cross-reference engine** — Phases 0–5 done on a branch, **not merged to main**. Phase 6 (gold-set
  eval, Celery, review UI) not started.
- **Reproducibility receipt** — make it real: key management, verification endpoint, a public
  verifier page. This is the differentiator; everything else is a statistics package.

## Phase 4 — Publication

Zenodo DOI exists; BMC submission is ready; bioRxiv v2 is blocked. PLOS desk-rejected on scope (the
third such rejection — the pattern is that the work is framed as a *tool* for a *methods* venue).

**The strongest paper this project can now write is not "here is our tool."** It is the thing that
actually happened here: *a statistics platform whose own numbers were wrong in eight distinct ways,
each one invisible to a green test suite, and the discipline that found them.* The calibration
benchmark (Fig 8) and the fabrication taxonomy in `DEFECTS_AND_PATTERNS_2026-07-14.md` are more
novel — and more useful to the field — than another power calculator.

Consider that framing before the next submission.

## The one thing to carry forward

Every fix in this arc shipped a new bug of the same class, one call site to the left — **eight times
in a row.** More care did not fix it; structure did:

> **One rule, one place. Mutation-check every test. Execute the artifact, don't read it. Never type a
> number you have not run.**

Those four lines are the actual deliverable of the last month. They are worth more than any feature
on this roadmap.
